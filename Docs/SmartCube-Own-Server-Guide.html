SmartCube Mobile · for Dad

Run your own SmartCube server

Your app currently talks to Dan's live server, which only works while his laptop is on. These steps put a complete private copy of the server on your own PC, with an empty database, so you can work any time and never touch real users.

The only time you need Dan's laptop is step 1, to download the zip files. Ask him to leave it on for ten minutes, or have him send you the two zips another way.

One-off setup

  1. Get the code

    Sign in to the admin page as RAY, find Drop zone, and click server zip and app zip. Unzip each somewhere on your C: drive, outside OneDrive, for example:

    C:\Dev\smartcube-server
C:\Dev\smartcube-app

    Each zip contains one folder with a long name. That folder is the project.

  2. Create your settings file

    In the server folder, copy appsettings.Example.json and name the copy appsettings.json. Leave it as it is. It points at a database called SmartCubeDev on your PC.

  3. Create your database

    Open PowerShell in the server folder (in File Explorer, click the address bar, type powershell and press Enter), then paste:

    powershell -ExecutionPolicy Bypass -File .\Database\Apply-Migrations.ps1 -Server "(localdb)\MSSQLLocalDB" -Database SmartCubeDev -Create
    You should see "Created database SmartCubeDev" and then four lines starting "Applied:". The database is empty: no users, no tariffs.

    This uses LocalDB, which comes with Visual Studio. You only do this once.

  4. Run the server

    In Visual Studio 2022 choose File → Open → Project, pick SmartCubeMobileV2026.csproj in the server folder. In the toolbar's run dropdown choose SmartCube (dev) and press F5.

    Your browser opens on your own copy of the SmartCube website at http://localhost:5000. Leave it running while you work.

  5. Make a test account

    On that page click Register and create an account, for example username dadtest. It exists only on your PC.

  6. Point the app at your server

    Open the app folder's SmartCubeMobile.sln in Visual Studio, choose Windows Machine and press F5. On the sign-in screen click the small Server: line at the bottom and enter:

    http://localhost:5000

    Then sign in with your test account. To go back to the live server later, click the same line and leave it blank.

Day to day

Start the server (F5 in the server project), start the app, work. Nothing depends on Dan's laptop. When something is ready for Dan, drop the project folder onto the admin page's drop zone as usual; that is the only step that needs the live server.

"running scripts is disabled"Use the exact command in step 3, which includes -ExecutionPolicy Bypass.
The app says it can't reach the serverIs the server still running (step 4)? Is the address exactly http://localhost:5000, with http, not https?
The server fails to start with a database errorRun step 3 again. It is safe to repeat; it only adds what is missing.
Anything elseCopy the error text and send it to Dan.
